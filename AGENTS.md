# Repository workflow

This is a Vietnamese personal finance calendar with default years 2026–2033 and editable active years. Income/bonus/expenses, loans, card statements and balance share currencies.cash (default JPY); savings/goals share currencies.savings (default VND) and must never be subtracted from JPY without an explicit exchange-rate feature. Archiving a year preserves its financial records for restoration. Use the existing checkout; do not create another Git worktree unless the user asks.

## Development

- Node.js >=22; no dependency installation is required. Editing requires a verified signed-in Supabase user. Enter or Save Changes explicitly submits a snapshot; typing only caches an account-scoped draft. Cross-device sync uses Supabase Auth and the public configuration in `src/config.js`; database setup is in `supabase/setup.sql`. Never put service_role/secret keys in browser code.
- Run `npm run dev` to start the development server on port 5173.
- Run `node test/model.test.js`, `node test/sync.test.js`, `node test/admin.test.js` and `npm run build`. Validate relevant browser interactions when changing UI behavior. Supabase row-level security and optimistic revision checks must remain enforced; never silently overwrite an account's cloud data with a local draft.
- Preserve browser-local financial data. Never commit financial backups, secrets, `.env` files, generated `dist/` files or temporary browser artifacts.

## User-authorized GitHub updates

The repository owner requested that completed code changes made by ChatGPT be committed and pushed to `Wang03062001/webapp-calendar` on `main`. Carry this preference forward in tasks working on this repository, unless the user's current instructions say otherwise.

- After completing an authorized edit, run appropriate checks, review the diff, commit the relevant changes with a descriptive message, and push to `origin main` without asking for the same permission again.
- Check the current branch and remote state first. If working on another branch, preserve existing work and integrate changes safely; never overwrite remote work or force-push to fulfill this preference.
- Reuse the platform's existing Git authentication. Do not put access tokens in files or ask for secrets in chat.
- If access, branch protection, failed checks, conflicting changes or a platform restriction prevents the update, report the precise blocker and preserve the work. Never claim GitHub has updated until the push and remote commit verification succeed.
- This is an agent workflow, not a background synchronization service. It applies while an agent is executing an authorized task in this repository; unrelated ChatGPT conversations cannot automatically change GitHub.

## Administration

Supabase server-only admin and username login setup is documented in `supabase/ADMIN.md`. Never trust user_metadata role flags, ship service-role keys to the browser or hardcode a default admin password. Regenerate Dashboard function bundles with `node scripts/build-edge-functions.mjs` after modifying Edge Function source. Preserve RLS and banned-account guards when editing migrations.

Money displays use en-US comma grouping with no forced trailing decimals (1,000,000; 1,234.5). Group monetary inputs as the user types and preserve the caret. Preserve numeric JSON storage and up to three-decimal precision; monetary text inputs must parse formatted numbers without changing their value. Use the shared readable typography tokens (12/14/16/18/24/32px), adequate text contrast, a sticky Save header and responsive reflow. Month pages must use only the selected month for totals and charts; year pages show annual aggregates. Debt payments in JPY create one linked expense on the payment date atomically with the debt ledger; preserve payment history and linked expense metadata through sync and backups.

New expenses default to planned; legacy expenses without status remain paid to preserve existing totals. Only paid expenses reduce period balance; planned totals are separate. Balance means period income minus paid spending, not a wallet balance with opening funds. Preserve expense categories/status, debt dueDate and payment voided flags in backups. Canceling a debt payment must atomically remove only its linked expense and retain a voided history entry; reject repeated cancellation and principal below active payments. Debt deletion is allowed only with no payment history. Month search and analytics must stay within the selected period.

Credit card rules: new one-off purchases default to next calendar month, with editable billingMonth; only explicit ribo purchases add to revolving debt. Card statement = oneOff + principal + fees; carry = priorBalance + newRibo - principal. Never hardcode the user’s private statement values or treat 25,000 JPY as a universal payment. Confirmed statements create exactly one protected fee expense; settlement/undo changes source cashflow/status and materializes/removes one protected cardPaymentMonth row, excluded from cost totals/charts so purchases/principal are not charged twice. Preserve cards settings/statements, expense paymentMethod/settlement/billingMonth/cardFeeMonth, and salary earnedMonth/receivedOn through sync/backups. Bank due date from a statement overrides the configurable expected date; confirmation date is explicitly entered. Do not assume a verified cutoff day or holiday calendar. Run node test/card.test.js with the other checks.

The Credit & statements module UI is admin-only: hide sidebar/shortcut/overview entry points until calendar_is_admin returns literal true for the current verified user; recheck on navigation/actions and before dialog submission. Fail closed on lookup errors, clear role state across account changes/logout, and close revoked dialogs. Do not trust user_metadata/email/username for role. Preserve existing owner-scoped document data; this menu restriction does not change the generic document RLS/write policy.

Year summary is last in navigation; sidebar uses verified profile username/current email and no ready/synced badge.

Language selection in Settings suggests both currency groups (vi=VND, en=USD, ja=JPY, ko=KRW, zh-TW=TWD). Account ledger: preserve optional accounts {openedOn,bank,cash,creditDebt,creditLimit:null|number,transfers:[]} and expense paymentMethod bank/cash/card; absent expense source remains cash, absent income account remains bank with receivedOn or month-15. Income account and debt payment source must survive normalization/backups. Balances include only paid/actual dated records from opening date (start-of-day snapshot) through selected day; never treat credit limit as cash or combine savings currencies implicitly. Transfers bank↔cash are internal and excluded from cost/income/outflow totals. Card settlements are rows keyed card-payment-YYYY-MM with cardPaymentMonth, protected from editing/deleting in expense UI. New paid statements must have a matching row; legacy paid statements lacking paymentSource migrate once to bank and one linked row. Undo validates the link before mutating; never silently delete manual expense rows to deduplicate. Costs/dayTotal/monthSummary/category charts exclude settlement rows; moneyOut and accountBalances count settlements once via statements and exclude linked rows from direct outflows. Show both cost and bank/cash outflow with explicit labels. Keep credit balance/limit UI and editing admin-only alongside existing credit rules. Required tests include node test/ledger.test.js.


Internal expense movements: movement=withdraw means bank→cash; deposit means cash→bank. Both are shown in daily expenses and search but excluded from incurred costs, planned costs/counts, card forecasts and external moneyOut. Source is forced to bank/cash respectively; forbid movement mixed with protected fee/debt/settlement metadata. Legacy accounts.transfers are rendered as virtual read-only expense entries, counted once through the existing transfer ledger. Remaining assets=bank+cash only.

Month-end reconciliation: optional accounts.reconciliations[] stores id/date(bank/cash actual,expectedBank,expectedCash,deltaBank,deltaCash,note). Require valid final-day date at/after openedOn, no future confirmation in UI/helper, exact signed delta validation. Preview before explicit confirmation, snapshot-check full finance data/user identity, append auto note preserving the day note and all transactions. Reconfirming appends audit history; latest array entry on the latest closing date is effective. Bank/cash balance uses that observed close and only later-dated movements, while credit debt continues from its original baseline. Historical entries/cost totals never get rewritten to explain discrepancies; do not add discrepancy income/expense. Use node test/reconciliation.test.js and browser verification of withdrawals, deposits, notes, month rollover and manual confirmation.

Fee visibility and ordinary-day corrections: cardFeeMonth rows are protected internal liability links only; exclude them from expense lists/search/categories/calendar/charts, spending totals and counts. Keep statement fees and include them once in total card payment; bank debit remains once and fee liabilities still feed credit debt. Shared data-money-kind palette is payment red, income green, bank blue, cash orange, card purple; mixed aggregates stay neutral. Existing-account ordinary-day corrections use accounts.reconciliations kind=manual with confirmedOn and max 3 successful confirmations per confirmation month. Preserve them through normalization/backups/account sync. Only successful optimistic server writes consume a slot; canceled/failed requests and month-end reconciliations do not. Never reset creditLimit, creditDebt, history or transactions to implement a correction. Test monthly quota, cancellation, failure/conflict, reload/account isolation, and browser flows with mocked data only.

Credit feature scope: use financeView(data, canUseCredit()) for all visible summaries, searches, category options, charts, bank/cash balances and reconciliation expected values. Never save the projection: retain hidden cards, linked fee/payment/purchase rows, credit-type debts and creditDebt/creditLimit in the full document. Ordinary accounts cannot select card payment methods or mutate hidden credit rows; literal server-verified true is required and revocation closes financial dialogs. Admin view keeps full original calculations. Full owner backups retain hidden data; owner-scoped JSON RLS is unchanged.

PayPay available-credit entry is admin-only and unlimited, independent of the three monthly bank/cash corrections. cards.availableCreditHistory stores end-of-day observed available amounts; latest date/latest same-day entry wins and only subsequent card purchases/fees/payments adjust it. Preserve through normalization and backups; never invent bank/cash opening balances or change debt/creditLimit to accept an available-credit observation. Reverify admin and full document snapshot before saving; no actual financial data in tests.

A–E regional books: root version-2 financial data remains the legacy/foreign book; optional regional.vietnam holds an independent normalized version-2 VND book. readBook/writeBook must preserve the inactive book, and never persist a role-filtered projection. Foreign setup supports JP/JPY, GB/GBP, KR/KRW, CN/CNY; VN salary defaults off. bookSettings.modules hides entry UI only; it never deletes data or changes totals. Switching regions must close dialogs and reject stale async mutations; all saves/backups include the full document and preserve optimistic revision checks. Never relabel a populated country or silently reinterpret legacy monthly savings currencies. Legacy data remains at its original location.

Actual savings source is accounts.savings in the cash currency (optional savingsOpenedOn). It is separate from legacy savings[month]/goals in currencies.savings. Bank is unallocated funds; assets=bank+cash+savings without double counting. Source transfers are internal; spending from savings is a cost and reduces assets once. Preserve savings in incomes, receipts, debt repayments, card settlement sources, transfer history and reconciliations; validate historical stock sufficiency before saving. Gifts/freelance/interest are other income; own remittance and receivable principal collections are non-income inflows. Receivable records are opening principal already owed, not a new cash disbursement. Reject over-collection and deletion of linked principal history. User records foreign outgoing and VND incoming independently: no FX/remittance automation. Three monthly balance corrections are per book; PayPay availability remains unlimited.

Vietnam/non-JP configured books use simple card statements (manual total/due date/status and payment source); no PayPay or revolving detail in that UI. Existing legacy books without country configuration retain old card mode. All card UI/actions remain verified-admin only; no SQL policy expansion. Use tests/regions.test.js plus optional scripts/check-regions-browser.mjs with mocked API; never use real finances/accounts for testing. Group F is implemented in safety-model.js/safety-ui.js; group G is not included.


Group F: per-book safety stores funds (dated earmark/release history), budgets, linked obligations, partial debt terms and reserve/payoff settings. Earmarks do not create assets; aggregate fund balances per source must not exceed historical source balances. Paid fundId expenses reduce earmarks and underlying source once, planned ones only affect forecast. Validate fund/source/link invariants on normalize/save; never silently release earmarks or fabricate stock. Budgets exclude internal transfers, card fees and settlements and distinguish actual from planned. Obligations link exactly one planned/paid expense, preserve due date and confirmation/undo audit, move to actual payment date on confirmation and restore original due date on undo. No direct edit/delete of linked expenses; retain paid history. Dialogs use full active-book snapshots, actor and region checks.

Forecast starts from actual closing source balances and applies dated inflows/outflows once over the next 30 days. Include overdue assumptions (next day), explicitly entered minima/statement totals, future actual repayments, internal transfers and earmark availability. Do not count card purchases as immediate cash payments, duplicate linked planned bills, forecast unknown values as zero or infer unentered recurring income. Partial loan terms use null for unknown APR/minimum; explicit APR 0 differs from missing. Payoff strategies are pure advisory monthly APR/12 simulations with minimums first, avalanche/snowball extra allocation, 600-month bound and insufficiency/non-amortization/missing flags. Card planning snapshot lives in cards.safetyPlan and is verified-admin only, as are credit-loan terms and card forecast source; ordinary projections hide those. No FX or group G calculations.

Actual debt payment.amount remains principal; optional interest stores explicitly paid charges. One linked expense equals principal + charges; only principal reduces debt. Cancel/normalize must verify the combined amount, source and paid status. Preserve legacy payments without charges. Source cash forecasts and minimum fulfillment count principal + charges once. Use test/safety.test.js and mocked scripts/check-safety-browser.mjs along with A–E regressions; never test against real finance/accounts.

An end baseline is month-end actual, so same-day transactions are excluded from later source calculations; a start baseline includes that day's transactions. Keep original accounts.openedOn/bank/cash/creditDebt/creditLimit and original credit chronology intact. sourceOpening() supplies the effective money/savings dates; credit before its original start is unknown, not zero. Preserve all later reconciliations, and reject openings after the earliest reconciliation. Opening edits share the existing 3-successful-updates-per-confirmation-month quota with manual corrections; failed/canceled/conflicting writes consume nothing. Known month closes continue through normal reconciliation without quota. Use full-book normalization, savings/fund sufficiency, account/region/epoch checks and commitConfirmed for the new dialog. Do not count carried funds as income, overwrite inactive books or apply this to real financial data in tests. Run test/opening.test.js and mocked scripts/check-opening-browser.mjs with existing regressions.
